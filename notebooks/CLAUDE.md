## Project Overview

Research project for learning and sampling zebrafish trajectories in response to visual stimuli using a probabilistic neural network (zero-inflated lognormal speed + Student-t orientation). Designed for semi-closed-loop behavioral paradigm with 15 fish, 30 fps, visual dot stimuli.

Requires Python 3.13. Dependency management via [uv](https://docs.astral.sh/uv/).

## Setup

```bash
uv sync          # install dependencies from pyproject.toml
uv pip install -e .  # install the src package in editable mode
```

## Script-based Workflow

The primary workflow is three scripts run in sequence:

### 1. Train
```bash
uv run scripts/train.py --config configs/default.toml --output runs/run_001/
```
Outputs: `checkpoint.pt`, `df_base.pkl`, `loss_curve.png`

### 2. Sample
```bash
uv run scripts/sample.py \
    --checkpoint runs/run_001/checkpoint.pt \
    --base       runs/run_001/df_base.pkl \
    --output     runs/run_001/samples/ \
    --n_trials   5
```
Outputs: `trial_000.csv`, `trial_001.csv`, ...

### 3. Compare
```bash
uv run scripts/compare.py \
    --samples    runs/run_001/samples/ \
    --real       abs_dict.pkl \
    --output     runs/run_001/comparison/
# dish geometry defaults to center=(180,174), radius=183.5 px; override with --dish_x/y/radius
```
Outputs: `speed_distribution.png`, `dori_distribution.png`, `position_heatmap.png`, `dist_center_distribution.png`, `autocorrelation.png`

### Creating a new experimental run

Copy and modify the config:
```bash
cp configs/default.toml configs/all_fish.toml
# edit fish_ids, hidden_sizes, num_epochs, etc.
uv run scripts/train.py --config configs/all_fish.toml --output runs/all_fish/
```

## Architecture

```
Raw experiment files
  └─► src/transformed_data_pipeline.py  → per-fish DataFrames (absolute + polar coords)
  └─► src/preprocessing.py              → feature engineering, lag features, train/sample splits
  └─► src/model_NN.py                   → train probabilistic NN, checkpoint I/O, model registry
  └─► src/sampling.py                   → autoregressive trajectory generation + video
  └─► src/functions.py                  → utilities: egocentric transforms, engineered features,
                                           lag creation, train/val/test split
  └─► src/analyse.py                    → coordinate utilities (cart2pol, pol2cart, etc.)
```

**Model**: single hidden-layer MLP → 5 outputs: `μ_st, σ_st` (Student-t for d_ori) + `p_pos, μ_ln, σ_ln` (zero-inflated lognormal for speed). Registry in `src/model_NN.py:MODEL_REGISTRY` — add new architectures there and register them.

**Checkpoint format** (saved by `save_checkpoint`, loaded by `load_checkpoint` in `src/model_NN.py`):
```python
{
    "model_state": ...,   # torch state dict
    "model_config": ...,  # type, hidden_sizes, n_features
    "scalers": ...,       # {"X": MinMaxScaler, "speed": MinMaxScaler, "ori": MinMaxScaler}
    "feature_cols": ...,  # list of input feature column names
    "config": ...,        # full TOML config dict
}
```

## Key Constraints & Parameters

- **`horizon_frames` must be 1 for sampling** — autoregressive generation requires frame-by-frame prediction.
- **Preprocessing and sampling must use identical `cols_to_lag`, `subsample`, `horizon_frames`** — stored in the checkpoint so scripts enforce this automatically.
- **Pass only a short segment to `sample_trajectory`** — it runs autoregressively from index 0; the first `max_lag_seconds` seed from real data.
- **Stimulus positions are NOT generated by the model** — copied from the input dataframe. Modify `d{k}_x`, `d{k}_y`, `d{k}_stim` columns to test specific conditions.
- **`train_nn_pipeline` returns 5 values** — `model, scalers, splits, train_losses, val_losses` (changed from notebooks).

### Default parameter values (configs/default.toml)
| Parameter | Value | Meaning |
|---|---|---|
| `fps` | 30 | frames per second |
| `subsample` | 1 | lag step in frames |
| `max_lag_seconds` | 3 | history window (= 90 frames) |
| `horizon_frames` | 1 | prediction horizon (must be 1 for sampling) |

## Dish Boundary Feature

The transformation pipeline normalises all fish to a shared per-dish coordinate frame, so dish geometry is the same for every fish:
- **Center**: (180, 174) px — estimated from fish trajectories
- **Radius**: 183.5 px — from 50 mm × MM_TO_PX (3.67 px/mm)

`stack_dict_pipeline(abs_dict, dish_x=180, dish_y=174, dish_radius=183.5)` attaches these as constant columns. `add_engineered_features` then computes:

```
dist_center = sqrt((f_x - dish_x)² + (f_y - dish_y)²) / dish_radius
```

This normalised radial position (0 = center, 1 = edge) is included in `cols_to_lag` by default. In practice `dist_center` stays well below 1.0 (observed max ~0.93). During sampling, `sample_trajectory` clamps the fish position to the dish boundary at every step.

## Data Format

Pre-transformed per-fish CSVs live in `data/df_transformed/` — one file per fish named `*_f{N}_transformed_abs.csv`. All fish share a common per-dish coordinate frame (the transformation pipeline normalises each fish to its own dish). Build `abs_dict.pkl` once:

```bash
uv run scripts/build_abs_dict.py --input data/df_transformed/ --output abs_dict.pkl
```

`abs_dict` is `{"f0": df_f0, ..., "f14": df_f14}`. Each DataFrame has columns: `frame`, `stimulus`, `f{N}_x/y/ori`, `d{k}_x/y/stim` for k in 0–7. No `source_frame` column (the script handles this gracefully).

Stimulus coordinates convention: left = positive x, right = negative x.

If you have the original raw files and need to re-run the transformation pipeline:
```python
from src.transformed_data_pipeline import generate_transformed_datasets
results = generate_transformed_datasets(stimuli_df, position_df, roi_df)
abs_dict = results["absolute"]
```
